# Muofu AI Quota Lens 仓库开源化与重置机会设计

状态：Accepted

日期：2026-08-30

目标仓库：`notuhao/muofu-ai-quota-lens`

## 1. 目标与范围

本阶段把现有 Firefox 扩展整理为可公开协作、可审计、可复现打包的开源仓库，并修复额度重置和套餐上下文的高风险误判。新增功能在不扩大权限、不读取认证信息、不主动调用私有用量 API 的前提下，被动显示 usage-limit reset credits 的数量与最近已观测到期时间。

范围包括：

- Git 仓库边界、文本属性、临时目录、公共文档和社区协作文件；
- 品牌、包名、制品名与目标 GitHub 仓库名同步；
- AMO 投递材料与公共源码解耦；
- 套餐变化、重置、窗口选择和异常时间的根因修复；
- reset credits 被动捕获、最小存储和临期提示；
- CI、可复现构建与 GitHub Release 草稿自动化；
- Mozilla、OpenAI 和上游许可边界的公开说明。

不包括：主动消耗 reset credit、自动 AMO 签名或发布、读取 Cookie/Token、创建或共享 ChatGPT 测试账号，以及替用户创建公开 GitHub 仓库。

## 4. Reset credits 被动数据流

### 4.1 上游事实

OpenAI 官方 `openai/codex` 当前契约区分：

- `/backend-api/wham/usage` 中的 `rate_limit_reset_credits.available_count`：当前可用数量摘要；
- GET `/backend-api/wham/rate-limit-reset-credits`：详情列表，其中 `credits[].expires_at` 是可空到期时间；
- POST `/backend-api/wham/rate-limit-reset-credits/consume`：消耗动作，本扩展不观察、不调用也不提供入口。

详情响应还可能包含 profile URL、profile user ID、credit ID、标题和描述。它们不属于本功能所需数据，必须在 MAIN world 首次白名单化时丢弃。

### 4.2 扩展内契约

`src/page-hook.js` 只对同源精确 GET 路径分类：

1. `credits_usage`：提取窗口、套餐提示和 reset credit 数量摘要；
2. `credits_daily`：提取按日 Credits/Tokens/Turns；
3. `reset_credits`：只提取 `availableCount`、可用项的有效 `expiresAt`，并派生最近到期时间。

`src/core.js` 对三类观察再次清洗。reset credits 的持久化模型为：

```text
schemaVersion
availableCount | null
nearestExpiresAt | null
nonExpiringObservedCount
summaryObservedAt | null
detailsObservedAt | null
detailsLoaded
```

不保存 credit ID、用户 ID、头像、授予人、标题、描述、原始数组、header、Cookie、Token 或原始响应。`availableCount` 以服务端摘要为准；详情数量不代替摘要数量。

`src/bridge.js` 将最新状态保存到独立 key `ccwResetCreditsLatestV1`。usage 摘要和详情可以任意顺序到达：数量为 0 时清除旧到期详情；数量大于 0 但详情较旧时保留详情时间戳并由 UI 显示观测时间，不伪装成实时状态。

## 5. UI 与时间规则

Popup 和 Dashboard 均显示：

- 可用重置机会数量；
- 最近**已观测**到期时间；
- 详情最后观测时间或“到期详情尚未被页面加载”；
- 数据过期/需重载提示。

临期分级使用文字与样式共同表达：

- 距到期不超过 7 天：`warning`；
- 距到期不超过 72 小时：`danger`；
- 到期时间已经过去且没有更新：`stale`，提示重新加载官方 Usage 页面；
- 无到期时间的可用项只显示“观察到不设到期项”，不推断永久有效。

扩展不会根据本地时钟自行减少服务端 `availableCount`。所有时间以 ISO instant 存储，以用户本地时区显示。

按钮优先打开官方当前路径 `/codex/settings/usage`；旧 `/codex/cloud/settings/analytics` 继续作为兼容路径识别，但不再作为公共文档的首选入口。

## 6. 套餐、重置与窗口安全不变量

1. 套餐上下文只有双方都缺失，或双方存在且精确相等时才可比较；一方未知、一方已知时不可比较。
2. `pro_ambiguous` 只能与相同上下文比较，不能与 `pro5x` 或 `pro20x` 比较。
3. 套餐变化必须先于周期 key 相等判断。即使 `cycleStart/resetAt` 尚未变化，也要形成 `plan_change` 边界并进入首点保护。
4. 未按用量捕获时间关联的路由记录不得影响 Credits 套餐、基线或参考告警。路由套餐只在路由诊断区展示。
5. 用户明确选择套餐时，只影响之后的新捕获；设置变更后当前比较进入待刷新状态，不把旧估计静默套用到新套餐。
6. 窗口遍历支持 bounded object/array；只有 5–9 天窗口可以成为 `weeklyWindow`。不存在时显示不可用，不回退到任意窗口。
7. 单个无效、负数、超范围或不可表示的 `reset_at` 不得使整次 usage 捕获失败。
8. 重置边界日仍属于不确定日桶；首点仅作暂定显示，同周期 delta 一旦可用即完全优先。

## 7. 路由观察边界

路由功能继续只保存模型标识、请求/会话关联 ID、时间、来源和诊断结果，不保存提示词、回答或原始帧。WebSocket 观察移除没有当前证据支持的任意 `*.openai.com` 范围，仅接受 ChatGPT 明确允许的主机范围，并继续要求存在待关联的会话请求。

## 8. 权限、隐私与合规

Manifest 权限保持精确不变：

```json
"permissions": ["storage"],
"host_permissions": ["https://chatgpt.com/*"]
```

不增加 `authenticationInfo`。扩展没有开发者服务器、遥测、远程代码、主动私有 API 请求或认证信息读取路径，`data_collection_permissions.required = ["none"]` 继续与当前数据流相符。

公开文档必须同时披露：

- 私有页面字段可能变化，观测结果不是 OpenAI 官方额度证明；
- 页面 MAIN world 不可信，数据不是密码学证明；
- OpenAI 服务条款对自动化提取和逆向分析存在实质不确定性，开源、本地处理与被动观察不会自动消除该风险；
- AMO 功能审查若要求账号，不得共享个人 ChatGPT 凭据，应使用审查员自有账号、获授权测试账号或事先取得 Mozilla 接受的演示方式。

## 9. 构建、CI 与 Release

- Node 基线提升为 22+，与当前 `web-ext` v10 要求一致。
- 精确锁定 `web-ext` 开发依赖并提交 lockfile。
- `npm run check` 运行功能测试与静态隐私审查；`npm run lint:addon` 运行 Mozilla linter；`npm run package` 生成确定性未签名 XPI、source ZIP 和 SHA256SUMS。
- 打包时间使用固定、文档化 epoch，源码 ZIP 可在无 Git 元数据时重建同字节 XPI。
- CI 仅有 `contents: read`，不接触 AMO secret。
- `v*` tag workflow 校验 tag、Manifest 与 package 版本一致，构建制品并创建 GitHub draft release。Release 明确标记 XPI 未签名，仅用于开发/审查；正式安装优先指向 AMO 签名版本。
- 不在普通 push、PR 或未经 Environment 审批的流程中运行 `web-ext sign`。

## 10. 测试与验收

功能测试覆盖：同周期/跨周期套餐变化、未知/冲突套餐、reset 与 plan 同时变化、边界保护、`additional_rate_limits` 数组、仅 5 小时窗口、异常 timestamp、reset count/detail 的乱序与不一致、可空/过期 expiry、敏感字段不进入 message/storage/export，以及 consume POST 不产生观察或额外请求。

UI 测试覆盖 count-only、detail-only、无数据、临期、紧急、已过期和本地时间显示；提示不能只依靠颜色。

仓库验收覆盖：ignored AMO 材料不在 `git ls-files`，源码 ZIP/XPI 不含 `.tmp` 或 Reviewer Notes，`npm run check`、`web-ext lint`、打包审计、校验和验证、`git diff --check` 和 workflow 静态检查。
